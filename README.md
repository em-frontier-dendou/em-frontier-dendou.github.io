# Emフロンティア殿堂 運営者向けの手引き

ポケモンエメラルドのバトルフロンティア7施設の、実機での記録を載せる記録表サイトです。個人が運営する非公式のファンサイトです。

この手引きは、運営者（プログラマーでない方）が、サイトを公開して記録を更新するためのものです。ふだんの更新は**スプレッドシートに行を足すだけ**で、コードには触りません。

GoogleやGitHubの画面は、ときどき名前や位置が変わります。下の手順と少し違っていたら、近い名前のボタンを探してください。

## 1. ファイルの一覧

| ファイル | 中身 | 運営者が触るか |
| --- | --- | --- |
| `index.html` | トップ（記録表） | 触らない |
| `rules.html` | 掲載ルール | ルールを変えるときだけ |
| `about.html` | このサイトについて | 文面を変えるときだけ |
| `player.html` | プレイヤーごとの全記録。記録表の名前を押すと開く（`player.html?name=掲載名`） | 触らない |
| `assets/config.js` | 3つの設定値（CSV・フォーム・チャンネルのURL） | **最初に1回だけ書き換える** |
| `assets/app.js` | 記録表の処理 | 触らない（ひらがなの表記を直すときだけ） |
| `assets/style.css` | 見た目 | 触らない |
| `data/sample.csv` | 架空のサンプルデータ。`csvUrl` が空のあいだだけ使う | 触らない |

記録そのものは、このフォルダ（リポジトリ）には入れません。Googleスプレッドシートにだけ置きます。

## 2. 最初にすること（4つ）

### 手順1　掲載用のスプレッドシートを作る

1. [Googleスプレッドシート](https://sheets.google.com/) を開き、「空白のスプレッドシート」を押して新しいファイルを作る。
   - **申請フォームの回答が入るファイルとは、必ず別のファイルにする**（回答には連絡先が入るため。掲載用のファイルは世界中に公開されます）。
2. 画面の下にあるシート名（「シート1」）をダブルクリックして、`掲載用` に変える。
3. 1行目に、次の見出しを1つずつ入れる。**名前はこのとおりに**入れてください（サイトは見出しの名前で列を探します）。列の順番は入れ替えても、列を足しても構いません。

   | 見出し | 入れるもの | 入れてよい値 |
   | --- | --- | --- |
   | ID | 行の通し番号 | 1、2、3… |
   | 掲載名 | 記録表に出す名前 | 文字 |
   | 施設 | 施設の名前 | `バトルタワー` `バトルドーム` `バトルパレス` `バトルアリーナ` `バトルファクトリー` `バトルチューブ` `バトルピラミッド` |
   | 形式 | シングルかダブルか | `シングル` / `ダブル`（アリーナ・チューブ・ピラミッドは `シングル`） |
   | レベル | レベル区分 | `レベル50` / `オープンレベル` |
   | 記録 | 記録の数字 | 数字だけ（「連勝」などの文字はつけない） |
   | 状態 | 記録が続いているか | `継続中` / `終了` |
   | 達成日 | 達成した日（継続中なら確認した日） | `2025-12-01` か `2025/12/1` の形。空でもよい |
   | パーティ | ポケモンの名前 | 文字（「・」で区切る） |
   | 本体 | 使った本体 | 文字。空でもよい |
   | 証拠 | 証拠の有無 | `証拠あり` / `自己申告` |
   | 証拠URL | 証拠の投稿へのリンク | `https://` で始まるURL。空でもよい |
   | 紹介リンク | noteや動画へのリンク | `https://` で始まるURL。空でもよい |
   | 表示 | サイトに出すか | `TRUE` / `FALSE` |

4. （おすすめ）打ち間違いを防ぐために、「施設」「形式」「レベル」「状態」「証拠」の列は、列を選んでからメニューの「データ」→「データの入力規則」→「ルールを追加」→「プルダウン」で、上の値を選べるようにしておく。「表示」の列は、列を選んでから「挿入」→「チェックボックス」にすると、チェックを入れたら `TRUE`、外したら `FALSE` になります。

書き方の見本は、このフォルダの `data/sample.csv` です（中身は架空のデータ）。

### 手順2　シートをCSVで公開して、URLを config.js に入れる

1. 掲載用のスプレッドシートで、メニューの「ファイル」→「共有」→「ウェブに公開」を押す。
2. 「リンク」のタブで、左のプルダウン（「ドキュメント全体」）を `掲載用` に変える。
3. 右のプルダウン（「ウェブページ」）を `カンマ区切り形式（.csv）` に変える。
4. 「公開」を押し、確認の画面で「OK」を押す。
5. 出てきたURL（`https://docs.google.com/spreadsheets/d/e/…/pub?…output=csv` の形）をコピーする。
6. そのURLを、`assets/config.js` の `csvUrl` に入れる（入れ方は「[4. 設定を書き換える](#4-設定を書き換えるconfigjs)」）。

公開されるのは「掲載用」のシートの中身だけです。ただし `表示` が `FALSE` の行も、CSVのURLを直接開けば見えます。**公開したくない情報（連絡先、了承前の本名など）は、掲載用のファイルに書かないでください。**

### 手順3　申請用のGoogleフォームを作って、URLを config.js に入れる

1. [Googleフォーム](https://forms.google.com/) で申請用のフォームを作る。
2. フォームの右上の「送信」（または「公開」）を押し、リンクのマーク（🔗）を選んで、URLをコピーする。
3. そのURLを、`assets/config.js` の `formUrl` に入れる。

`formUrl` が空のあいだ、「記録を申請する」のボタンは「このサイトについて」の「申請の方法」へ飛び、そこには「申請フォームは準備中です。」と出ます。URLを入れると、ボタンはフォームへの外部リンクに変わります。

### 手順4　GitHub Pages を有効にする

1. このフォルダの中身を、GitHubのリポジトリの `main` ブランチに上げる。
2. GitHubでリポジトリのページを開き、上のメニューの「Settings」を押す。
3. 左のメニューの「Pages」を押す。
4. 「Build and deployment」の「Source」を `Deploy from a branch` にする。
5. 「Branch」を `main`、その右を `/ (root)` にして、「Save」を押す。
6. 数分待ってからページを開き直すと、上のほうにサイトのURL（`https://ユーザー名.github.io/リポジトリ名/`）が出る。

## 3. 記録を足す・隠す・直す

どれも、掲載用のスプレッドシートを直すだけです。サイトは、開かれるたびにシートを読みに行きます。**シートを直してからサイトに出るまで、5分ほどかかることがあります**（Google側の反映を待つため）。

### 記録を足す

1. いちばん下の空いている行に、1件分を入力する。
2. 内容を確かめてから、`表示` を `TRUE` にする（チェックボックスならチェックを入れる）。

- 同じ人の記録が同じ区分（施設・形式・レベル）に複数あっても構いません。記録表には、いちばん大きい記録の1件だけが出ます。ほかの記録は、記録表の名前を押すと開くプレイヤーのページに、順位「—」として出ます。掲載名は一字一句同じにしてください（違う名前だと別の人として出ます）。
- 並び順は、サイトが自動で決めます（記録の大きい順。同じ数字なら達成日の早い順。達成日が空の行は、同じ数字の中でいちばん下）。シートの行の順番は関係ありません。
- フッターの「最終更新」には、出している全記録の達成日のうち、いちばん新しい日が出ます。

### 申請フォームから届いた記録を足す

申請の回答が入るスプレッドシート（「Emフロンティア殿堂 記録の申請（回答）」）に、`転記用` というタブがあります。回答を掲載用と同じ列の並びに直して、自動で表示するタブです。連絡先と備考は入りません。

1. 回答のスプレッドシートの `転記用` タブを開き、載せる申請の行の **B列からM列** を選んでコピーする（A列の申請日時はコピーしない）。
2. 掲載用のシートで、空いている行の **B列** をクリックし、`Ctrl` + `Shift` + `V`（値のみ貼り付け）で貼り付ける。ふつうの `Ctrl` + `V` だと、計算式ごと貼られて正しく出ません。
3. `証拠` の列を確かめる。`転記用` では、証拠のURLがあれば `証拠あり`、なければ `自己申告` と自動で入ります。写真の確認などで判断が変わるときは書き直す。
4. 内容を確かめてから、`表示` にチェックを入れる。

- `証拠URL` は、申請者が「証拠のリンクを記録表に載せてよい」に「はい」と答えたときだけ入ります。
- フォームの選択肢には英語が添えてあります（例：`バトルタワー (Battle Tower)`、`継続中（記録がまだ続いている） (Ongoing)`）。`転記用` タブでは、かっこの部分を取り除いて `バトルタワー`、`継続中` のように掲載用と同じ値にして出します。
- `本体` は複数選べる質問です。2つ以上選ばれたときは、`ゲームボーイアドバンスSP／ニンテンドーゲームキューブ＋ゲームボーイプレーヤー` のように「／」で区切って入ります。
- `転記用` タブの A2 のセルには計算式が入っています。消したり上書きしたりしないでください。

### 記録を隠す（了承待ち、取り下げ）

その行の `表示` を `FALSE` にする（チェックを外す）。行を消す必要はありません。

### 記録を直す

その行のセルを書き直すだけです。継続中の記録が止まったら、`記録` を最終の数字に、`状態` を `終了` に、`達成日` を止まった日に直します。

### 行が出てこないとき

`表示` が `TRUE` なのに出ない行は、「掲載名」「施設」「形式」「レベル」「記録」のどれかが空か、決まった値と違っています（例：`バトル タワー`、`Lv50`、`100連勝`）。サイトはそういう行を飛ばします。どの行を飛ばしたかは、ブラウザでサイトを開いて F12 キーを押し、「Console」のタブを見ると、行番号つきで出ています。

## 4. 設定を書き換える（config.js）

書き換えるのは `assets/config.js` の3つの値だけです。

```js
window.SITE_CONFIG = {
  csvUrl: '',      // 掲載用シートの公開CSVのURL
  formUrl: '',     // 申請用Googleフォームの URL
  channelUrl: ''   // YouTubeチャンネルのURL
};
```

GitHubの画面で書き換える手順：

1. リポジトリのページで、`assets` → `config.js` の順に押して開く。
2. 右上の鉛筆のマーク（Edit this file）を押す。
3. `''`（シングルクォート2つ）のあいだにURLを貼る。例：`csvUrl: 'https://docs.google.com/spreadsheets/d/e/…/pub?gid=0&single=true&output=csv',`
   - `'` と、行の終わりの `,` を消さないように気をつける。
   - URLは必ず `https://` で始まるもの。それ以外は、サイトが無視します。
4. 右上の「Commit changes...」を押し、出てきた画面でもう一度「Commit changes」を押す。
5. サイトに反映されるまで、数分から10分ほど待つ。変わらないときは、ブラウザで Ctrl + F5（強制の再読み込み）を押す。

| 値 | 空のあいだ | 入れたあと |
| --- | --- | --- |
| `csvUrl` | 架空のサンプル（`data/sample.csv`）を表示 | 掲載用シートの記録を表示 |
| `formUrl` | 申請ボタンは「このサイトについて」の「申請の方法」へ | 申請ボタンはGoogleフォームへ |
| `channelUrl` | 運営者名はただの文字 | 運営者名がチャンネルへのリンクになる |

## 5. 手元のパソコンで見る

`index.html` をダブルクリックして直接開くと、ブラウザの決まりで記録を読み込めず、「記録を読み込めませんでした。」と出ます（故障ではありません）。手元で見るときは、次のようにします。

1. このフォルダをエクスプローラーで開き、上のアドレス欄に `powershell` と打って Enter を押す。
2. 出てきた黒い画面に、次の1行を打って Enter を押す（Python が入っている場合）。

   ```powershell
   python -m http.server 8000
   ```

3. ブラウザで `http://localhost:8000/` を開く。
4. 終わるときは、黒い画面で Ctrl + C を押す。

Python が入っていなければ、GitHubに上げてから公開されたサイトで確かめるのが、いちばん手軽です。

## 6. うまくいかないとき

| こうなったら | 確かめること |
| --- | --- |
| 「記録を読み込めませんでした。」と出る | `csvUrl` のURLが正しいか。シートが「ウェブに公開」されているか（公開を止めていないか）。1行目の見出し（掲載名・施設・形式・レベル・記録・表示）の名前を変えていないか。URLをブラウザに貼って開くと、CSVのファイルが落ちてくるか。 |
| シートを直したのにサイトが変わらない | 5分ほど待って、開き直す。 |
| 記録が1件だけ出てこない | 「[行が出てこないとき](#行が出てこないとき)」を見る。 |
| リンクが出ない | 証拠URL・紹介リンクが `https://` で始まっているか（`http://` は出ません）。 |
| 架空のサンプルが出たまま | `csvUrl` が空のまま。「4. 設定を書き換える」を見る。 |

シートのURLが正しいのに、いつまでも読み込めないとき（ブラウザの Console に「CORS」と出るとき）は、**自分で仕組みを変えずに**、Claude Code に相談してください。代わりの案は、GitHub Actions で定期的にCSVを取ってきて `data/records.csv` として保存し、サイトはそれを読む形です。

## 7. 守ること

1. ゲームの画像・ロゴ・公式イラスト・ドット絵・シンボルの絵柄を、サイトにもリポジトリにも置かない。証拠の写真も置かず、投稿先へのリンクにする。
2. 非公式であることの表記（全ページのフッター）を消さない。
3. リポジトリに、実在の人の名前や記録を入れない。本番の記録はスプレッドシートにだけ置く。`data/sample.csv` は架空のままにする。
4. アクセス解析、広告、Cookieは入れない。

## 8. 文面や表記を直す場所

| 直したいもの | 場所 |
| --- | --- |
| 記録の数字の後ろのひらがな（「れんしょう」など。実機で要確認のもの） | `assets/app.js` のいちばん上の「施設の一覧」の `kana`。ここ1か所を直せば変わる |
| 掲載ライン（「70連勝」など） | 同じ「施設の一覧」の `line`。あわせて `rules.html` の表も直す |
| 掲載ルールの本文 | `rules.html`（元の原稿は `rules.md`。両方を同じ文面にしておく） |
| 「このサイトについて」の本文 | `about.html` |
| フッターの非公式の表記 | `index.html` `rules.html` `about.html` のいちばん下（3ページとも同じ文にする） |

区分ごとのURLは、`https://…/?f=バトルチューブ&l=レベル50` の形です（`f` は施設、`m` は形式、`l` はレベル）。サイトでボタンを押すとアドレス欄が変わるので、それをコピーすれば、その表に直接リンクできます。
